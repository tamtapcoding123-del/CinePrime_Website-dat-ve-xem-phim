# PHẦN MỞ ĐẦU
## 1. PHÂN TÍCH HIỆN TRẠNG
- Khách xem phim cần một website xem lịch chiếu, chọn ghế theo sơ đồ, thanh toán trực tuyến và nhận vé QR ngay trên điện thoại.
- Khó khăn của rạp chiếu phim bao gồm:
+ Tranh chấp ghế: nhiều khách cùng chọn một ghế tại cùng thời điểm.
+ Xếp lịch chiếu: nhiều phòng, nhiều phim; phải tránh trùng giờ và chừa thời gian dọn phòng.
+ Thanh toán: phải xác thực kết quả từ cổng thanh toán, không phát vé sai.
+ Soát vé: mỗi vé chỉ vào một lần, đúng rạp, đúng khung giờ.
## 2. MỤC ĐÍCH
### 2.1. Mục đích của sản phẩm
- Xây dựng website đặt vé xem phim trực tuyến cho khách hàng, kèm trang quản trị cho Admin và Staff.
- Giúp khách đặt vé nhanh, không cần xếp hàng tại quầy.
- Giúp rạp quản lý phim, lịch chiếu, đơn hàng, doanh thu và soát vé tập trung.
### 2.2. Mục tiêu hệ thống
- Cho phép khách tìm phim, xem lịch chiếu, chọn ghế và thanh toán trực tuyến.
- Đảm bảo một ghế chỉ bán cho một khách, kể cả khi nhiều người đặt cùng lúc.
- Giúp Admin xếp lịch chiếu theo tuần, quản lý giá, đơn hàng và xem báo cáo.
- Giúp Staff soát vé bằng mã QR và bán vé tại quầy.
### 2.3. Tính năng cơ bản của hệ thống
- Tìm kiếm và xem phim: lọc theo thể loại, ngày, độ tuổi; xem lịch chiếu theo rạp.
- Đặt vé: chọn ghế thường, VIP, ghế đôi; giữ ghế 5 phút; thêm combo, áp voucher.
- Thanh toán an toàn: thanh toán qua ví MoMo, xác thực chữ ký của cổng thanh toán.
- Vé điện tử: mỗi ghế một mã QR; tải vé PDF; nhận email xác nhận.
- Quản lý tài khoản: đăng ký, đăng nhập, quên mật khẩu, lịch sử đơn, điểm thưởng.
- Quản trị: phim, rạp, phòng, sơ đồ ghế, giá, lịch chiếu, combo, voucher, người dùng.
- Staff: check-in vé bằng QR, bán vé tại quầy, quản lý ca thu tiền mặt.
- Báo cáo: doanh thu, số vé, lấp đầy theo ngày, tuần, tháng, năm; xuất CSV.
### 2.4. Đối tượng sử dụng
- Quản trị viên (Admin)
- Nhân viên (Staff)
- Khách hàng (Customer)
### 2.5. Công nghệ dùng để phát triển dự án
- Ngôn ngữ: Java 25, HTML, CSS, JavaScript, SQL
- Framework: Spring Boot 4.1 (Spring MVC, Spring Security, Spring Data JPA)
- Giao diện: Pug4J (render phía máy chủ), CSS và JavaScript thuần
- Database: MySQL 8, quản lý phiên bản bằng Flyway
- Thanh toán: MoMo (môi trường thử nghiệm)
- Thư viện: PDFBox (vé PDF), ZXing (mã QR), Apache POI (Excel)
- Kiểm thử: JUnit 5, kiểm thử tích hợp trên MySQL
- Xác thực: Session, CSRF, băm mật khẩu

# CHƯƠNG I: CƠ SỞ LÝ THUYẾT
## 1. MÔ HÌNH CÔNG NGHỆ
[hinh] D:\0_JAV102\CinePrime_Project\.claude\skills\cinebaocao\hinh-ly-thuyet\client-server.png | Client - Server | 12
- Client-Server: máy khách (trình duyệt) gửi yêu cầu, máy chủ xử lý và trả kết quả. Ở CinePrime: trình duyệt ↔ ứng dụng Spring Boot ↔ MySQL.
- Điểm mạnh:
+ Kiểm soát và bảo mật dữ liệu tập trung ở máy chủ.
+ Dễ mở rộng, dễ bảo trì.
- Điểm yếu:
+ Dễ quá tải khi nhiều yêu cầu cùng lúc.
+ Phụ thuộc vào tài nguyên máy chủ.
## 2. NGÔN NGỮ JAVA
- Java là ngôn ngữ lập trình hướng đối tượng, chạy trên máy ảo JVM, độc lập nền tảng. Dự án dùng Java 25.
- Ưu điểm:
+ Kiểu dữ liệu chặt chẽ, phát hiện lỗi sớm khi biên dịch.
+ Hệ sinh thái thư viện lớn, chạy ổn định trên nhiều hệ điều hành.
+ Hỗ trợ đa luồng, phù hợp xử lý nhiều yêu cầu đồng thời.
- Nhược điểm:
+ Cú pháp dài hơn một số ngôn ngữ khác.
+ Tốn nhiều bộ nhớ hơn.
## 3. SPRING BOOT
- Spring Boot là framework giúp dựng ứng dụng Java nhanh, đóng gói thành một file JAR chạy độc lập. Dự án dùng Spring MVC, Spring Security, Spring Data JPA, Validation và Mail.
- Ưu điểm:
+ Cấu hình tự động, ít mã khởi tạo.
+ Tích hợp sẵn bảo mật, truy cập dữ liệu, gửi email.
+ Cộng đồng lớn, tài liệu đầy đủ.
- Nhược điểm:
+ Nhiều tầng trừu tượng, khó nắm cơ chế bên trong lúc đầu.
+ Thời gian khởi động và dung lượng lớn hơn ứng dụng nhẹ.
## 4. MÔ HÌNH MVC
- MVC (Model-View-Controller) là mô hình kiến trúc chia ứng dụng thành ba phần:
[hinh] D:\0_JAV102\CinePrime_Project\.claude\skills\cinebaocao\hinh-ly-thuyet\mvc.png | Mô hình MVC | 11
+ Model: dữ liệu và nghiệp vụ (entity, service).
+ View: giao diện hiển thị (template Pug).
+ Controller: nhận yêu cầu, gọi nghiệp vụ, chọn View trả về.
- Luồng xử lý:
+ Trình duyệt gửi yêu cầu đến Controller.
+ Controller gọi Service/Model xử lý và lấy dữ liệu.
+ Controller chuyển dữ liệu cho View, View trả HTML về trình duyệt.
## 5. CƠ SỞ DỮ LIỆU: MYSQL
- MySQL là hệ quản trị cơ sở dữ liệu quan hệ mã nguồn mở. Dự án dùng MySQL 8 và Flyway để quản lý phiên bản cấu trúc bảng.
- Ưu điểm:
+ Hiệu suất cao, ổn định, dễ cài đặt.
+ Hỗ trợ giao dịch (transaction) và khóa dòng, đảm bảo toàn vẹn dữ liệu khi nhiều người đặt ghế.
+ Có nhiều công cụ quản trị và sao lưu.
- Nhược điểm:
+ Khi dữ liệu rất lớn cần tối ưu thêm (chỉ mục, phân tải).
+ Một số tính năng nâng cao hạn chế hơn các hệ quản trị khác.
## 6. XÁC THỰC VÀ BẢO MẬT
- Session: sau khi đăng nhập, máy chủ lưu phiên và gửi cookie cho trình duyệt.
- CSRF: mỗi yêu cầu thay đổi dữ liệu phải kèm token để chặn giả mạo yêu cầu.
- Mật khẩu được băm trước khi lưu; phân quyền theo vai trò Customer, Admin, Staff ở phía máy chủ.
- Ưu điểm: máy chủ kiểm soát phiên, có thể thu hồi ngay khi khóa tài khoản hoặc đổi quyền.
- Nhược điểm: máy chủ phải lưu trạng thái phiên.
## 7. CỔNG THANH TOÁN MOMO
- MoMo là ví điện tử. Dự án dùng phương thức captureWallet: máy chủ tạo yêu cầu, khách thanh toán trên MoMo, MoMo gửi kết quả về qua IPN.
- Mọi yêu cầu và kết quả đều ký HMAC; máy chủ kiểm tra chữ ký, mã đơn, số tiền trước khi xác nhận.
- Ưu điểm: thanh toán nhanh, có môi trường thử nghiệm (sandbox).
- Nhược điểm: phụ thuộc dịch vụ bên thứ ba; cần khóa và cấu hình riêng khi chạy thật.

# CHƯƠNG II: PHÂN TÍCH VÀ THIẾT KẾ HỆ THỐNG
## 1. PHÂN TÍCH NGHIỆP VỤ
### 1.1. Nghiệp vụ của Quản trị viên
- Quản lý phim: thêm, sửa, ẩn phim; mỗi phim có ngày khởi chiếu và ngày kết thúc.
- Quản lý rạp, phòng chiếu, sơ đồ ghế và giá vé theo phòng.
- Quản lý suất chiếu: xếp lịch theo tuần, nhập/xuất Excel, chặn trùng giờ.
- Quản lý combo, voucher, điểm thưởng, banner và nội dung.
- Quản lý người dùng: phân quyền, khóa tài khoản, phân Staff về rạp.
- Quản lý đơn hàng: tra cứu, đối soát thanh toán, hủy đơn chưa thanh toán.
- Thống kê: doanh thu, số vé, lấp đầy; xuất CSV; xem nhật ký thao tác.
### 1.2. Nghiệp vụ của Nhân viên
- Check-in vé: quét mã QR hoặc nhập mã thủ công.
- Chỉ xử lý vé thuộc rạp được phân công; mỗi vé chỉ vào một lần.
- Xem danh sách suất chiếu và vé trong ngày tại rạp của mình.
- Bán vé tại quầy: mở/đóng ca, chọn ghế, thu tiền mặt, in vé.
### 1.3. Nghiệp vụ của Khách hàng
- Xem phim: danh sách, chi tiết, lịch chiếu theo rạp và ngày.
- Đặt vé: chọn ghế (giữ 5 phút), thêm combo, áp voucher.
- Thanh toán: qua ví MoMo; nhận vé QR và vé PDF.
- Tài khoản: đăng ký, đăng nhập, quên mật khẩu, xem lịch sử đơn.
- Tương tác: yêu thích, đánh giá phim, nhận thông báo nhắc suất chiếu.

#### 3.1.1. Đăng ký tài khoản (AccountService.register)
- Mô tả:
+ Kiểm tra mật khẩu: ít nhất 10 ký tự, tối đa 72 byte.
+ Chuẩn hóa email (bỏ khoảng trắng, chữ thường), kiểm tra đúng dạng và họ tên không rỗng.
+ Nếu email đã tồn tại thì từ chối với thông báo chung (không lộ email nào đã đăng ký).

[ma]
public User register(String email, String name, String password) {
    passwordValid(password);
    email = email.trim().toLowerCase(Locale.ROOT);
    if (!email.matches("[^\\s@]+@[^\\s@]+\\.[^\\s@]+") || email.length() > 254
            || name.isBlank() || name.length() > 100)
        throw new IllegalArgumentException("Kiểm tra email và họ tên.");
    if (db.first(User.class, "where e.email=?1", email).isPresent())
        throw new IllegalArgumentException(
            "Không thể đăng ký email này. Hãy đăng nhập hoặc khôi phục mật khẩu.");
    User u = new User();
    u.email = email;
    u.name = name.trim();
    u.passwordHash = encoder.encode(password);
    return db.save(u);
}

### 3.3. Thanh toán (Tích hợp MoMo)
- Mô tả: MomoService.ipn nhận thông báo kết quả từ MoMo (IPN).
+ Kiểm tra mã merchant (partnerCode) đúng cấu hình.
+ Dựng chuỗi chữ ký từ các trường MoMo gửi, tính HMAC-SHA256 bằng khóa bí mật và so sánh với chữ ký nhận được.
+ Tìm giao dịch theo mã đơn MoMo và kiểm tra requestId khớp.
+ Chuyển cho BookingService.paymentResult kiểm tra số tiền và xử lý lặp lại an toàn; thanh toán đến muộn sau khi hết hạn giữ ghế chỉ được ghi nhận để đối soát, không phát vé.
- Mã nguồn:
[ma]
public void ipn(Map<String, Object> data) {
    if (!configured() || !partner.equals(data.get("partnerCode")))
        throw new IllegalArgumentException("Merchant không hợp lệ.");
    String raw = canonical(data, "accessKey", "amount", "extraData", "message",
        "orderId", "orderInfo", "orderType", "partnerCode", "payType",
        "requestId", "responseTime", "resultCode", "transId");
    String expected = sign(secret, raw);
    String actual = Objects.toString(data.get("signature"), "");
    if (!MessageDigest.isEqual(expected.getBytes(StandardCharsets.US_ASCII),
                               actual.getBytes(StandardCharsets.US_ASCII)))
        throw new IllegalArgumentException("Chữ ký không hợp lệ.");
    Payment p = db.first(Payment.class, "where e.externalOrderId=?1",
        Objects.toString(data.get("orderId"))).orElseThrow();
    if (!p.requestId.equals(data.get("requestId")))
        throw new IllegalArgumentException("Request không khớp.");
    bookings.paymentResult(p.externalOrderId,
        Long.parseLong(data.get("amount").toString()),
        Objects.toString(data.get("transId")),
        Integer.parseInt(data.get("resultCode").toString()));
}

public Ticket checkIn(Long staffId, Long ticketId, Long selectedShowtime) {
    Ticket t = db.lock(Ticket.class, ticketId);
    Showtime s = db.get(Showtime.class, t.showtimeId);
    permitted(staffId, s);
    Instant now = clock.instant();
    Eligibility e = eligibility(t, s, db.get(Order.class, t.orderId), selectedShowtime, now);
    if (!e.allowed()) throw new StaffProblem(e.code(), e.message());
    t.status = "USED"; t.checkedInAt = now; t.checkedInBy = staffId;
    db.audit(staffId, "CHECK_IN", t.code);
    return t;
}

[ma]
java -jar target\cineprime-1.0.0.jar

## 3. Triển khai lên Vercel (dự kiến, chưa thực hiện)
- Vercel hỗ trợ chạy ứng dụng đóng gói bằng Docker (Container runtime), nên Spring Boot được triển khai bằng một Dockerfile; ứng dụng phải lắng nghe cổng do biến PORT cung cấp.
- Các bước dự kiến:
+ B1: Chuẩn bị MySQL trên dịch vụ ngoài (Vercel không cung cấp MySQL); cập nhật DB_URL, DB_USER, DB_PASSWORD.
+ B2: Viết Dockerfile build file JAR và chạy bằng JDK 25.
+ B3: Khai báo biến môi trường trên Vercel: DB_URL, DB_USER, DB_PASSWORD, khóa MoMo, SMTP, UPLOAD_DIR.
+ B4: Đẩy mã nguồn lên GitHub, kết nối repository với Vercel và deploy.
+ B5: Gắn tên miền, bật HTTPS, cấu hình địa chỉ IPN của MoMo về tên miền thật.
- Lưu ý: thư mục tải lên (UPLOAD_DIR) cần lưu trữ ngoài vì máy chủ chạy container không giữ dữ liệu lâu dài. Phần này chưa có cấu hình và chưa được kiểm thử, nên không ghi là đã triển khai.
